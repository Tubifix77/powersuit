The two-board bench: B is the orchestrator, C is the limb

For docs/bringup.md Appendix A. Each board gets one SN65HVD230 transceiver module (four wires), the two modules are joined by two more, and one wire ties the two boards' grounds together. Boards B and C keep their own USB cables, on the COM socket. Board A and its serial adapter are not part of this.

Five rules.
  • Use the board pins printed 3V3, 4, 5 and G on header J1 (3V3 at the antenna end), plus the G at the top of header J3 for the ground tie.
  • Board 4 → module TX, board 5 → module RX. Straight, not crossed. The module's TX pin is its transmitter's input; it takes what the ESP32 wants to send.
  • The module's supply goes to the board's 3V3. Never to 5V.
  • Match every wire by its printed label, never by counting positions.
  • Wire with B and C unplugged, then plug them back in.
3V3 → 3.3V G → GND 4 → TX 5 → RX CANH ↔ CANH CANL ↔ CANL G ↔ G, board to board
Drawn as it sits on the bench: each board with its antenna up, USB down, header J1 on its left and J3 on its right; each module to the left of its board, turned 180° so its four-pin header faces the board. Seen from above, the module's right edge reads top to bottom TX, RX, GND, 3.3V, and its far side CANL above CANH. The blue screw terminal carries CANH and CANL in parallel with the pins; either works for the bus, and leaving the terminal free lets you clamp meter probes on a live bus.

The wires, one table

#fromtonote
1board B 3V3 (J1 pin 1)module B 3.3Vpower
2board B G (J1 pin 22)module B GND
3board B 4 (J1 pin 4)module B TXstraight
4board B 5 (J1 pin 5)module B RXstraight
5–8the same four for board C and module C
9module B CANHmodule C CANHH to H
10module B CANLmodule C CANLL to L
11board B G (J3 pin 1)board C G (J3 pin 1)ground tie

Eleven jumper wires, all female-female. No resistors: each module carries its own 120 Ω terminator, which is exactly right for a bus with two nodes, one at each end. Use the usual colours for the real jumpers — red for power, black for ground, yellow for CANH, green for CANL — so the finished bench is easy to check against this page.

Why wire 11. The module's header has a single GND pin and wire 2 already uses it, so the boards tie their grounds directly. Two boards on the same PC share ground through it anyway; but in the test, the orchestrator runs from the mains charger, whose output floats, and CAN needs a common reference. Any G pin works — J3 pin 1 is simply the free one nearest the antenna.

What runs on them

  1. Build both roles (Docker must already be running — the script checks, and never starts it): 
    bash firmware/tools/build_bench.sh
  2. Flash each board through its COM socket. This replaces the sibling project's firmware on B and C: 
    powershell -File firmware/tools/flash_bench.ps1 -Role orch -Port COM4
powershell -File firmware/tools/flash_bench.ps1 -Role limb -Port COM5 -Monitor
  3. Move B to the charger. The orchestrator needs no console once flashed. C stays on the PC with its monitor open.
  4. Watch C. Amber while B is off: STANDBY, no heartbeat, no authority. Plug B's charger in: within a few hundred milliseconds C pulses white-blue, OPERATIONAL.
  5. Pull B's charger lead. C must go amber within 50 ms and log >>> 2 -> 3 (cause 6) — OPERATIONAL to PASSIVE, cause COMM_LOSS. That is the dead-man switch.
Do not open B's console during the test. Opening a board's serial port resets it (the DTR/RTS auto-reset wiring), so the beats stop and C trips — for the wrong reason, looking exactly like the test passing. To watch a board that is already running, use esp_idf_monitor --no-reset.
If C never reaches OPERATIONAL, read C's 2-second status line: rx_frames at zero means wiring (TX/RX swapped is the usual one); bus_errors climbing with wiring checked twice means try a lower rate on both boards — BENCH_CAN_BITRATE=500000 bash firmware/tools/build_bench.sh, the rate measured clean on these modules. Both boards print their rate at boot, and the two must match.
